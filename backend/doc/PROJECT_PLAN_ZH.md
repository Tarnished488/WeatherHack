# MajiGuard：社区用水压力风险与行动建议系统

MajiGuard 是 Hack The Weather 的环境数据决策支持原型。它将官方 Conduit@Empathy 环境数据转化为清晰、可解释且审慎的行动建议，帮助用户理解天气条件可能如何影响短期用水压力。

> **重要范围边界：** MVP 只能使用官方 Conduit CSV 中实际存在的字段。除非数据已经验证支持，否则不得宣称项目能够测量水质、水量、洪水概率、作物实际需水量或健康风险。这些能力只能作为后续扩展方向，不能写成 MVP 已实现功能。

---

## 1. 问题定义

社区可以看到天气读数，但仍然难以回答一个实际问题：**现在应该采取什么行动，为可能增加的用水压力做好准备？**

连续低降雨、高温、低湿度和强风，可能增加蒸发并提高家庭或小规模农业的用水压力；突发强降雨则可能意味着需要及时检查储水、排水或相关设施。

原始图表并不能直接帮助人决策。MajiGuard 将近期 Conduit 观测数据转换为：

1. 透明的用水压力风险等级；
2. 该风险等级背后的数据原因；
3. 面向居民、小农户和社区管理者的行动建议。

## 2. 目标用户与价值

| 用户 | 需要做的决策 | MajiGuard 提供的价值 |
|---|---|---|
| 社区居民 | 今天是否应节水或做好储水准备？ | 简洁易懂的风险提示和准备建议。 |
| 小农户 | 是否应重新评估灌溉时间？ | 基于天气条件的蒸发与降雨趋势提示，不提供作物处方。 |
| 社区管理者 | 应优先沟通或检查什么？ | 带有证据和优先级的告警记录。 |

## 3. MVP 范围

### 3.1 做什么

- 读取官方 Conduit CSV 数据。
- 校验、清洗和聚合实际提供的传感器字段。
- 计算可解释的 `低 / 中 / 高` 用水压力风险等级。
- 在网页中展示当前风险、历史趋势、告警和行动建议。
- 让每一条告警都能追溯到来源数据及风险规则。

### 3.2 不做什么

- 不输出医疗、公共卫生或饮用水安全结论。
- 不输出精确灌溉水量或作物专属建议。
- 不宣称可做权威洪水预测。
- 不假设 CSV 中存在水质或水量字段。
- 不直接控制水泵、灌溉设备或公共基础设施。

## 4. 产品功能详细介绍

### 4.1 风险总览 Dashboard

- 显示当前风险：低 / 中 / 高。
- 展示最新可用的关键环境指标。
- 展示排名最高的三个风险原因，例如“选定周期内累计降雨偏低”或“高温且低湿度”。
- 标注数据更新时间，避免用户误以为数据实时且完整。

### 4.2 可解释风险引擎

MVP 优先使用规则引擎，而不是不可解释的黑箱模型。这样更容易验证，也便于在比赛答辩中说明系统为什么给出某项建议。

| 信号 | 示例解释 | 对结果的影响 |
|---|---|---|
| 滚动周期降雨低于近期本地基线 | 持续干燥条件 | 提高用水压力分数 |
| 高温 + 低湿度 | 蒸发条件更强 | 提高用水压力分数 |
| 强风 + 高温 | 蒸发暴露进一步增加 | 提高用水压力分数 |
| 降雨突增 | 需要检查短期储水和排水准备 | 产生独立的准备提醒 |
| 数据缺失、过期或明显不合理 | 数据不足以支持可靠判断 | 降低置信度并展示数据质量告警 |

每一次 API 返回都包含风险分数、置信度和触发规则。阈值写入可版本管理的配置文件，在分析真实 CSV 分布后调整。

### 4.3 行动建议中心

建议属于决策支持，而不是对用户的强制指令。

- **居民：** 评估非必要用水；在符合当地条件时考虑安全储水；关注当地管理部门通知。
- **农户：** 在使用水资源前，复核灌溉安排、作物和土壤实际状况；优先遵循当地农业指导。
- **管理者：** 考虑发布社区提醒；检查近期数据质量；当风险持续时检查排水或储水设施。

### 4.4 趋势与告警历史

- 展示过去 7 天及可选周期的关键指标趋势。
- 展示风险分数随时间的变化。
- 展示告警历史：发生时间、触发规则、目标用户和建议行动。

### 4.5 数据透明度页面

- Conduit 数据来源和 CSV 获取日期。
- 实际使用的字段、单位和聚合频率。
- 缺失值、异常值的处理方式。
- 风险规则版本和已知局限性。

## 5. 技术架构

```text
官方 Conduit CSV
        |
        v
Python 数据读取与校验
        |
        +--> 清洗后的观测数据（SQLite）
        |
        v
可解释风险引擎
        |
        v
FastAPI REST API
        |
        v
React Web Dashboard（风险、趋势、建议、透明度）
```

## 6. 技术栈

| 层级 | 技术 | 用途 |
|---|---|---|
| 数据处理 | Python 3.12、Pandas | CSV 读取、清洗、滚动统计和趋势特征。 |
| 数据校验 | Pydantic、自定义校验规则 | 类型、范围、数据新鲜度和缺失值校验。 |
| 后端 | FastAPI、Uvicorn | 提供文档化 REST API 和风险计算服务。 |
| 数据存储 | SQLite（MVP） | 存储清洗数据、规则结果和告警。 |
| 前端 | React、TypeScript、Vite | 构建响应式 Web 产品界面。 |
| 可视化 | Recharts | 绘制趋势图和风险图。 |
| 样式 | Tailwind CSS | 快速构建统一界面。 |
| 质量保障 | Pytest、ESLint | 测试风险规则/API 和前端质量。 |
| 交付 | GitHub、Docker Compose | 可复现运行和源码提交。 |

仅当不会影响 MVP 完成时，再考虑加入 PostgreSQL、Leaflet 地图，或轻量异常检测模型。

## 7. 项目构建步骤

### 步骤 1：确认数据契约

1. 下载官方 Conduit CSV。
2. 记录字段名、单位、时间范围、时间戳格式、缺失值模式和传感器采样频率。
3. 只选择已验证存在的字段进入 MVP，并记录暂不可用的目标字段。
4. 如完整数据不应提交到仓库，创建小型样例 CSV 用于自动化测试。

**产出：** `docs/data-dictionary.md` 数据字典和字段—功能映射表。

### 步骤 2：构建数据处理管道

1. 实现 CSV 读取和时间戳标准化。
2. 校验数值范围；对可疑数据打标而不是静默删除。
3. 按小时或天聚合观测数据。
4. 对实际存在的字段计算滚动降雨、温湿度、风和数据新鲜度特征。
5. 保存清洗后的观测数据和校验结果。

**产出：** 可重复执行的数据处理命令，例如：

```bash
python -m app.ingest --source data/conduit.csv
```

### 步骤 3：实现并测试风险引擎

1. 在 JSON/YAML 文件中定义可版本管理的阈值。
2. 计算风险分数、置信度、触发规则和行动建议模板。
3. 编写低降雨、高温、降雨突增、数据缺失和正常状态的单元测试。
4. 使用多个真实 CSV 时间段验证输出，并在不夸大精度的前提下调整阈值。

**产出：** 可解释、可复现且有测试覆盖的风险结果。

### 步骤 4：实现后端 API

至少提供以下接口：

- `GET /api/current-risk`
- `GET /api/trends?metric=&period=`
- `GET /api/alerts`
- `GET /api/data-transparency`
- `POST /api/refresh`：仅用于开发和 Demo 刷新数据

**产出：** FastAPI OpenAPI 文档和 API smoke tests。

### 步骤 5：构建网页界面

1. 实现包含风险标签、关键读数、风险原因和行动建议的主页。
2. 实现趋势分析页和告警历史页。
3. 实现数据透明度页，方便评委核验 Conduit 数据的实际作用。
4. 处理加载、空数据、错误和数据过期状态。

**产出：** 可在浏览器中完成“数据 → 风险 → 行动”演示的 MVP。

### 步骤 6：整合、录制与提交

1. 用真实 CSV 跑通完整数据管道。
2. 确认前端界面与后端 API 结果一致。
3. 准备截图、架构图、README 和 3–5 分钟 Demo 视频。
4. 检查 GitHub 可访问，且未提交 token、密码或个人凭据。
5. 填写 Devpost 项目页；使用无痕窗口测试全部链接。
